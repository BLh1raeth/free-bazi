# JavaScript / TypeScript 历法库评估

评估日期：2026-08-03。界面与工程结构未采用第三方 GitHub 模板；本文件只评估历法依赖。

## 结论

首版采用 `lunar-typescript@1.8.6`，在 `src/lib/bazi/calendar-adapter.ts` 后面建立统一适配层。它不是 UI 的直接依赖，也不是本项目唯一真值来源；关键案例同时对照香港天文台历书/转换表与公开天文历法资料。

## 采用库的能力与边界

- 公历 / 农历互转、闰月：支持；产品限制为 1900–2100；
- 干支：提供以立春精确时刻换年的年柱、以节精确时刻换月的月柱、两种晚子时日柱规则和时柱；
- 节气：提供秒级交接时刻；上游说明算法以寿星天文历为基础；
- 时区：库自身不是 IANA 时区引擎。本项目使用 Temporal 将用户出生地民用时转换为真实瞬间，再转换到 `Asia/Shanghai` 供节令判断；
- DST：由 IANA tzdb / Temporal 解释。春季跳时中不存在的当地时刻明确拒绝；秋季重复时刻采用 Temporal `compatible` 的较早偏移；
- 自动化测试：上游仓库有 TypeScript 源码；本项目另有独立边界测试；
- 许可：MIT，可用于本项目，发布时保留依赖许可证。

## 依赖用途

- `lunar-typescript`：公农历、节气和干支基础数据；
- `@js-temporal/polyfill`：IANA 时区、DST、日期运算和真实瞬间比较；
- `zod`：出生输入验证；
- `html-to-image` / `jspdf`：用户点击后动态加载的免费导出；
- React / Next / Tailwind：界面与工程；
- Vitest / Playwright / ESLint / Prettier：质量检查。

## 迁移策略

适配层只向 UI 暴露项目内的 `BirthInput`、`BaziChart`、`Pillar` 与流运模型。未来迁移到 Tyme 时，先让同一批公农历、节令前后一分钟、23:00、DST 与大运案例全部通过，再替换适配器，UI 无需改动。
